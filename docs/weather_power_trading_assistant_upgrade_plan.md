## 1. 执行摘要

云云已经具备较好的天气机器人底座，但暂时还不是可以直接用于电力交易判断的决策助手。

下一轮开发必须先完成四个 P0：

1. 封堵未鉴权 HTTP 接口绕过群聊门禁直接发送飞书消息；
2. 禁止大模型仅凭天气判断电价方向或给出交易策略；
3. 修复“数据截止时间”不代表真实抓取时间的问题；
4. 结构化 `@云云` 必须核验机器人 `open_id`，不能只看显示名称。

在上述四项完成并通过回放门禁前，不开放主动预警、不扩大群发范围，也不输出更强的供需、电价或交易策略判断。

本规划阶段未修改业务代码、未部署、未重启服务、未向飞书发送消息，也未操作禁止服务器。

### 3.2 P0 缺陷

#### P0-1：未鉴权发送旁路

`services/weather_bot/main.py` 中以下 HTTP 接口没有统一鉴权和发送策略：

- `/api/weather/publish`
- `/api/tasks/weather/publish`
- `/api/tasks/weather/remind`

它们可以向默认飞书群发送卡片，却不经过结构化 mention、订阅确认、目标白名单或 `POWER_BRIEFING_ALLOW_SEND`。`docker-compose.yml` 同时映射 `8001:8000`，因此属于代码层 P0。

修复要求：

- 所有发送统一经过 `SendPolicy`；
- 默认关闭外部发布接口；
- 管理 API 增加 Token、来源网络限制、角色权限、幂等键和审计；
- 生产服务优先只绑定 `127.0.0.1`；
- 发送必须同时满足全局开关、目标白名单、授权来源和非 DRY_RUN。

#### P0-2：LLM 交易结论越界

`services/weather_bot/llm.py` 当前允许仅凭气象数据给出方向性供需、价格影响和交易策略思路，与晨报边界冲突。

修复要求：

- 建立确定性 `DecisionBoundary`；
- 仅有天气数据时，只输出气象事实、气象侧代理和待核查项；
- 接入负荷和出力后，才可解释供需变化；
- 只有具备负荷、机组、联络线、价格和市场规则时，才可提供有条件的市场情景；
- 永远不得输出自动交易、确定性报价、仓位或收益指令；
- 在 LLM 调用前后各执行一次边界校验。

#### P0-3：数据时间不真实

当前 `data_cutoff_time` 是按目标日前一天 16:00 计算的业务时间，不是实际抓取、数据源起报或聚合完成时间。

必须拆分为：

- `retrieved_at`
- `provider_issued_at`
- `aggregation_completed_at`
- `valid_time`
- `forecast_run_id`
- `business_submission_deadline`

如果 D-1 16:00 是任务截止，应明确叫“业务提交截止时间”。

#### P0-4：mention 未核验机器人身份

当前结构化 mention 主要按名称别名匹配。必须改成：

1. 首选 mention 中的机器人 `open_id/user_id`；
2. 校验其与当前 `bot_role/app_id` 的绑定；
3. 名称仅作为受控兼容降级；
4. 同名普通用户不得触发机器人。

## 4. 产品定位与能力边界

核心定位：

> 云云把复杂气象信息翻译成电力市场参与者能够理解、核查和进一步行动的气象侧风险信号。

### 4.1 外部数据优先的硬约束

项目不提供本地气象原始数据，也没有自有的负荷、出力、机组、联络线、价格、持仓或用户资产数据。所有业务事实只能来自第三方 API、官方公开数据或能够回溯到原始发布方的公开搜索结果。

本地系统的职责仅限于：

- 数据源注册、访问配置和权限控制；
- 有保留期限的请求缓存；
- 不可变预报版本快照及来源元数据；
- 聚合特征、风险结果、质量评分和审计记录；
- 脱敏后的失败信号和自动回放样本。

本地系统不得：

- 将搜索摘要、新闻转载或大模型记忆当成结构化事实数据；
- 在第三方接口失败时补造数值；
- 把历史缓存描述为最新数据；
- 把第三方代表点数据包装成全省实况；
- 声称拥有尚未取得的数据接口或数据授权；
- 长期保存超出许可、必要性或保留期限的第三方原始数据。

外部数据来源优先级：

1. 官方或数据发布机构的结构化 API；
2. 已签约、许可清晰的专业数据服务；
3. 官方公开网页、公告、文件及可验证下载；
4. 搜索引擎仅用于发现原始来源，不直接作为数值真值；
5. 无法定位原始来源时，只能作为待核查线索，不进入计算和预警。

任何进入业务计算的数据必须附带：

- `source_id` 和原始来源 URL/API；
- `retrieved_at`；
- `provider_issued_at`（能够取得时）；
- `valid_time`；
- 数据单位、粒度、覆盖范围和时区；
- 许可/使用范围；
- 完整率、质量状态和降级原因；
- 内容哈希或可重放请求标识。

每项新能力必须先通过 `DataAvailabilityGate`：确认来源存在、可持续访问、许可允许、时效满足、字段足够且有失败降级方案。门禁未通过时，只保留能力说明或 DRY_RUN 原型，不得上线为真实结论。

| 层级 | 可以输出 | 数据要求 |
|---|---|---|
| W1 气象事实 | 温度、体感、降水、风、辐照、预警、预报变化、源间分歧 | 气象数据 |
| W2 电力气象代理 | 负荷天气压力、光资源、风资源、水文气象、新能源预测复杂度 | 气象及历史气象 |
| P1 电力市场解释 | 实际负荷、净负荷、风光预测偏差、供需变化 | 负荷、实际出力、预测、机组、联络线 |
| A1 资产决策 | 仓位、报价、储能调度、机组运行建议 | 用户资产、合同、持仓、价格及约束 |

仅有天气数据时的统一回答：

> 当前可以确认的是：明日 17:00–21:00 存在体感高温持续、制冷度时上升的气象侧负荷压力。是否造成实际负荷明显增长或日前价格上涨，仍需结合负荷预测、新能源预测、机组可用率、联络线和报价数据复核；目前不能仅凭天气判断价格方向。

禁止输出：

- “明天山东价格会上涨”；
- “建议做多”；
- “买入 100MWh”；
- “光伏将少发 500MWh”；
- “负荷一定增加 3GW”。

### 6.1 外部数据适配架构

每个外部来源使用独立适配器，并统一输出标准化结果：

```text
第三方 API / 官方公开页面
→ SourceRegistry 来源与许可检查
→ ExternalDataAdapter 抓取
→ Schema / 单位 / 时区校验
→ Provenance 元数据补全
→ 完整率与新鲜度门禁
→ 有限期缓存和不可变版本快照
→ 聚合、指标和报告
```

适配器必须支持：

- 明确超时、重试和总体截止时间；
- 请求限流、配额和成本监控；
- 内容结构变更检测；
- 来源不可用时的降级，不跨来源静默补值；
- DRY_RUN 和回放 fixture；
- 原始数据最小化保存及自动清理；
- 对网页搜索类来源保留原始链接、发布时间和抓取证据。

公开搜索适合发现政策、公告、预警和市场披露入口，不适合作为小时级数值预报、负荷、出力或价格的主要计算来源。高频或结构化能力必须依赖稳定 API、官方文件下载或许可明确的数据服务。

## 7. 电力气象指标体系

| 指标 | 推荐口径 | 能说明 | 不能说明 |
|---|---|---|---|
| 制冷度时 CDH | `Σmax(T_effective-BaseCool,0)` | 制冷气象压力 | 实际制冷负荷 |
| 采暖度时 HDH | `Σmax(BaseHeat-T_effective,0)` | 采暖气象压力 | 实际采暖用电 |
| 持续高温 | 地区阈值以上连续小时数 | 高温持续性 | 负荷增加 MW |
| 负荷天气压力 | CDH/HDH、湿热、持续性、突变的历史分位组合 | 相对常年压力 | 峰值负荷、电价 |
| 光伏资源代理 | 优先 GHI/DNI/DHI、晴空比；缺失时才用云雨降级 | 光资源强弱 | 场站实际出力 |
| 光资源转弱 | 目标期相对昨日同版、今日或晴空基线的变化率 | 资源转弱幅度 | 减发 MWh |
| 地面风代理 | 10 米平均风、阵风、方向和持续性 | 近地风变化 | 轮毂风、风机功率 |
| 轮毂风估算 | `Vhub=Vref×(Hhub/Href)^α` | 粗略轮毂风 | 未校准场站真实风速 |
| 风功率密度 | `0.5×ρ×Vhub³` | 风资源潜力 | 风机实际功率 |
| 风电爬坡风险 | 风速变化率、风向突变、阈值穿越、源间分歧 | 资源快速变化概率 | 实际爬坡 MW |
| 电网友好性风险 | 官方预警、雷电、大风、冰冻、高温、暴雨组合 | 气象危险 | 实际线路故障概率 |
| 水文气象代理 | 流域累积降水、前期降水、土壤湿度、融雪及滞后 | 来水气象条件 | 实际入库流量 |
| 新能源预测偏差风险 | 多源离散、版本修订、爬坡、对流性、历史技巧 | 天气难预测程度 | 偏差 MW |
| 预报版本变化 | 同地点、同有效时间，不同发布版本的差值 | 风险为何变化 | 实况必然变化 |
| 数据源分歧 | 对齐单位、时刻后计算极差、标准差和技巧归一分歧 | 不确定性来源 | 多数源必然正确 |
| 置信度 | 覆盖率×新鲜度×历史技巧×一致性×代表性 | 结论可信程度 | 大模型主观判断 |
| 连续风险窗口 | 连续至少 2 小时，最多合并 1 小时间隙，恢复采用滞回 | 开始、峰值、结束 | 分钟级事件 |

现有 26℃/18℃只能作为透明降级基准。后续应按地区、季节、工作日类型和负荷类别校准，全国排行应比较历史分位。

### 7.1 时间尺度

| 时效 | 推荐表达 |
|---|---|
| 0–6 小时 | 结合雷达、卫星、实况和官方预警，表达概率和落区 |
| 日内剩余时段 | 使用最新运行版本，明确相较晨报是否上调 |
| 次日 | 可给连续窗口、驱动、变化和置信度 |
| 未来 3 天 | 给逐日风险演变 |
| 未来 7 天 | 给过程和大致窗口，降低确定性 |
| 8–15 天 | 只给概率、距平和趋势 |
| 月度/季节 | 多情景和历史分位，不给确定日级结论 |

所有输出必须展示生成时间、抓取时间、数据源起报时间、有效时间、时区、预报时效、比较版本、置信度和降级原因。

## 21. 当前实现的生产发布安全清单

本节是当前实现的强制发布门禁；若与前文的时间预估或“建议”措辞冲突，以本节的 fail-closed 要求为准。

### 21.1 数据所有权与来源门禁

云云没有本地自有气象或电力事实库。第三方 API、官方公开数据和公开搜索发现的原始材料，是事实的唯一可能来源；本地只保存：

- 有界缓存；
- 不可变的预报版本和 provenance 元数据；
- 许可允许的派生特征、风险结果和质量分；
- 脱敏审计、幂等键和自动回放记录。

生产 `WEATHER_SOURCE_POLICIES_JSON` 默认必须为 `[]`。这会让 `SourceRegistry` 拒绝所有未配置 provider/endpoint，让 `DataAvailabilityGate` 在聚合和业务计算前返回数据不可用。不得因为已有 Key、测试能访问、供应商名称熟悉或页面公开，就把 `license_status` 猜成 `verified`。

每项来源必须由人工逐项审核并留痕：

| 检查项 | 必须记录的结论 |
|---|---|
| 身份 | provider、产品/套餐、精确 endpoint URL 前缀、环境与责任人 |
| 权利 | 合同/条款版本、商业使用范围、允许的 `calculation`/`text_reference`/`derived_storage` |
| 署名 | 是否必须署名、准确文案与展示位置 |
| 存储 | 允许的缓存和保留期；当前服务只支持 `derived_only` 或 `metadata_only`，不支持 `raw_storage` |
| 数据契约 | required metrics、单位、覆盖模型、粒度、时区、最大数据年龄和最低完整率 |
| 运维 | 配额、限流、成本、失败降级、停服联系人和复核日期 |

只有上述结论通过审核后，才能由授权运维人员生成与 `APP_ENV=production` 精确匹配的 `SourcePolicy`。策略、真实 endpoint、许可范围和实际响应元数据任一不一致时均拒绝，不跨来源静默补值。

公开搜索只负责“发现原始来源”。必须继续打开并核验原始发布方 URL、发布时间和内容证据；摘要、转载和大模型总结只可作为待核查线索，不能进入数值计算、结构化预警、客观回测或负荷/出力/机组/价格结论。

### 21.2 官方预警接口边界

当前 QWeather 官方预警适配器使用：

```text
GET https://{reviewed-api-host}/weatheralert/v1/current/{latitude}/{longitude}
```

它不再把行政区划代码拼接到旧的 `/v7/warning/now` 路径。生产启用前必须独立审核实际 API host、当前合同/条款、`text_reference` 和 `derived_storage` 权限、署名要求及 endpoint 前缀。输出只保留预警 ID、标题、原始发布机构、发布时间、有效时间、失效时间、消息类型、来源标记、抓取时间、来源 URL/哈希和署名；第三方原始正文、处置说明、搜索摘要和凭证不落库。接口、策略或元数据不满足时统一返回“当前无法取得可靠官方预警数据”，不调用搜索或大模型补写。

### 21.3 09:00 任务、订阅与发送授权

现有北京时间 08:50 预计算和 09:00 计划发送定义必须保留。计划发送只有同时满足以下三项才允许执行：

1. `GLOBAL_FEISHU_SEND_ENABLED=true`；
2. `POWER_BRIEFING_ALLOW_SEND=true`；
3. 当前目标 `chat_id` 位于人工审核的 `POWER_BRIEFING_TARGETS_JSON`。

`DRY_RUN=true` 对以上结果拥有无条件否决权。目标列表为空、JSON 无效、目标重复或任一开关不满足时，只生成/读取快照，发送次数必须为 0，也不得占用成功发送幂等键。cron 只选择 `send` 模式，不得用命令行环境变量覆盖 `POWER_BRIEFING_ALLOW_SEND`。每个“日期化发布时次 + 目标 chat_id”必须通过持久化发送账本原子认领，并向飞书传递稳定 UUID；重复、并发和失败重试复用同一个 UUID。定时脚本和代码不得硬编码群 ID。

旧版 09:00 任务发布、16:30 提醒、17:00 预测节奏与晨报不是同一计划。它必须受独立且默认关闭的 `LEGACY_WEATHER_SCHEDULER_ENABLED` 控制，不能因晨报开启 `GLOBAL_FEISHU_SEND_ENABLED` 而被连带启用。

订阅授权与通知发送相互独立：

- 私聊草稿只有在同一用户、会话和机器人范围内明确回复“确认订阅”后才可激活；
- 群聊还需要已配置审核管理员在同一群、同一线程二次明确确认；
- “可以”“好的”等模糊确认不激活；
- `ACTIVE` 订阅不能绕过 `GLOBAL_FEISHU_SEND_ENABLED`、`ALERT_SEND_ENABLED`、目标范围、限频、静默时间、outbox 幂等和 `DRY_RUN`；
- 主动通知发送链、来源和目标白名单未独立验收前，生产保持 `ALERT_SEND_ENABLED=false`，不得补发历史积压。

每个生产目标必须记录准确 chat_id、用途、授权人、频率、静默时段、紧急停发责任人、首次批准日期和复核日期。密钥、Token、chat_id、open_id、内部许可材料及任何服务器凭证不得进入仓库、镜像、日志、测试 fixture 或本报告。

### 21.4 部署硬阻断条件

以下任一项未完成，发布结论必须是 **BLOCKED，不部署**：

- 所有将被调用的第三方来源均没有书面/工单化的人工许可结论；
- 生产 `SourcePolicy` 尚未按精确环境、provider 和 endpoint 复核；
- 生产所需 required metrics、单位、覆盖、时区、新鲜度、完整率或降级策略不完整；
- 晨报或预警目标未形成最小白名单，或授权人/紧急停发责任人不明确；
- bot open_id、管理员 open_id、管理 API 鉴权和密钥注入方式未复核；
- 96 条事件回放未全部通过，或全量测试中的新增失败尚未清零；
- 尚未完成配置解析、`DRY_RUN`、同一快照、重复 event_id/outbox 幂等和 0 次误发送验证；
- 上一稳定镜像/提交、配置哈希和相关数据库备份不可用；
- 监控、告警和一键关闭 `ALERT_SEND_ENABLED`/`GLOBAL_FEISHU_SEND_ENABLED` 的责任人未值守。

禁止用测试策略、虚构条款版本、示例 endpoint、测试 chat_id 或“先上线再补审批”绕过此门禁。当前默认 `WEATHER_SOURCE_POLICIES_JSON=[]` 和 `POWER_BRIEFING_TARGETS_JSON=[]` 正是有意的部署硬阻断，不是待随手补齐的普通配置。

### 21.5 灰度步骤

1. 固化待发布提交、依赖、镜像、配置 schema 和数据库迁移清单；备份数据库并验证可读。
2. 保持 `GLOBAL_FEISHU_SEND_ENABLED=false`、`ALERT_SEND_ENABLED=false`、`DRY_RUN=true`，完成 96 条回放、全量测试和同一快照晨报检查。
3. 使用审核后的来源策略影子运行至少 7 天，只抓取、门禁、计算和记录质量，不回复、不发送；逐项观察许可拒绝、完整率、新鲜度、配额和来源分歧。
4. 开放内部私聊白名单，继续禁止主动告警和群发送。
5. 仅对一个已审核的现有 09:00 目标开启晨报计划发送，观察至少一个完整发布周期；其他目标仍关闭。
6. 核对误回复、串上下文、重复发送、错误地点、版本错配、来源缺失和边界越界均为 0 后，再逐个扩展目标。
7. 订阅主动通知最后单独灰度，不与晨报开关同时扩大范围，也不补发灰度前事件。

### 21.6 回滚步骤

1. 立即关闭 `ALERT_SEND_ENABLED` 和 `GLOBAL_FEISHU_SEND_ENABLED`，确认发送次数停止增长。
2. 冻结未发送 outbox，禁止恢复后补发；保留审计记录和失败现场。
3. 保留 08:50/09:00 定时定义，但让其保持只计算/不发送；不要通过删除 cron 掩盖发送故障。
4. 恢复上一稳定镜像或提交及已验证配置；不执行破坏性数据库降级或删除新表。
5. 核对数据库版本、配置哈希、来源策略、目标白名单、bot 身份、event_id 幂等和晨报快照指针。
6. 在隔离环境用 `DRY_RUN` 重放故障，确认修复和回归测试后重新从单目标灰度开始。

只有来源许可、目标授权、测试证据、灰度责任人和可验证回滚同时齐备，当前工作区才具备生产部署资格。代码完成或提交成功本身不构成上线批准。
