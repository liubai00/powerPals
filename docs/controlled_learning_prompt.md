# 云云“受控持续学习 1.0”实施提示词

你是一名资深对话系统架构师、Python 工程师、气象评测工程师和生产安全负责人。请在 `weather_agent` 项目中实现云云的“受控持续学习 1.0”。这里的“学习”不是让机器人自行修改代码或直接上线，而是从自动构造案例、历史问题回放和预报实况评分中产生有证据、可测试、可审批、可回滚的改进候选。

## 项目与部署边界

- 本地项目：`D:\workspace\project\weather_agent`
- 正确生产服务器：`38.76.196.233`
- 禁止操作：`117.72.103.1`
- 保留用户已有未提交文件和修改，不得覆盖 `.claude/`、`.idea/` 等无关内容。
- 修改完成后运行目标测试和全量测试，区分新增失败、基线失败、过时预期和产品缺陷。
- 通过验证后提交并推送当前最新分支，再部署到正确生产服务器。
- 部署后验证健康接口、容器状态、模型配置、09:00 晨报任务和群聊严格门禁。

## 本期明确不做

- 不建设点赞、点踩或依赖大量用户对话的反馈系统。
- 不保存完整飞书聊天记录、用户隐私、Token、API Key 或服务器密码。
- 不允许学习任务调用飞书发送接口，不新增任何自动群发路径。
- 不允许模型自行修改生产代码、提示词、地点词典、数据源权重或配置。
- 不允许候选在审批后自动生效；审批只是审计状态，真正实施仍需代码审查、测试和部署。

## 必须实现的能力

1. 自动生成并回放意图、地点、范围、日期、天数、指标、上下文隔离和群聊干扰案例。
2. 支持管理员通过本地 CLI 增加少量高价值案例，输入必须结构化、可版本化、可停用。
3. 自动归档以下最小化信号：
   - 低置信度预报；
   - 单个或多个数据源不可用；
   - 所有数据源不可用；
   - 回放预期与实际不一致；
   - 实况接口暂不可用。
4. 每次成功预报后保存不可变预报快照，只保留评测所需的地区、坐标、目标日期、生成时间、来源和气象数值。
5. 目标日期结束且公开历史参考天气可用后，用它评估每个数据源；必须标明格点历史/再分析数据不等同于气象站实况：
   - 最高温误差；
   - 最低温误差；
   - 温度平均绝对误差；
   - 是否降水命中；
   - 10 米最大风速误差；
   - 综合分。
6. 按数据源、地区和预报提前量聚合结果；样本数不足时必须标记“证据不足”，不得给出权重调整结论。
7. 根据失败案例聚类和客观评分生成非执行型改进候选，至少覆盖：
   - 意图优先级；
   - 地点别名或范围规则；
   - 日期解析；
   - 指标解析；
   - 上下文隔离策略；
   - 群聊寻址门禁；
   - 数据源权重建议。
8. 候选具有 `pending / approved / rejected / rolled_back` 状态、证据、生成时间、决定人和决定时间；所有状态变更保留审计记录。
9. 每次周期运行输出 JSON 和 Markdown 报告，包含回放通过率、失败案例、信号统计、待评估快照、数据源评分、候选和安全边界。
10. 提供每日只读学习周期入口；它可以抓取公开实况并写本地数据库和报告，但不得发飞书、改配置、改代码或部署。

## 质量闸门

- 群聊未真实 @ 云云时，自动回复测试必须为 0。
- 伪造文本 `@云云` 但无结构化 mention 时，自动回复测试必须为 0。
- 不同用户、群、线程和机器人之间的上下文串话测试必须为 0。
- 当前消息显式实体必须覆盖历史实体；失败请求不得成为最近成功请求。
- 候选生成必须确定性、可重复，不能把大模型主观判断当作实况证据。
- 所有数据库写入失败必须降级，不得影响正常天气回复。
- 报告不得把演示、合成或样本不足的数据描述为真实结论，也不得把格点历史/再分析数据描述成官方站点实况。
