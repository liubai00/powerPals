# 云云电力气象交易晨报 3.1

> 状态：本地实现与离线测试版本。本文所有卡片示例均为演示数据，不代表真实预报。
> 本轮未部署、未重启服务、未发送飞书消息，也未把 `test` 群或任何其他群写入代码。

## 1. 产品目标

晨报不再罗列“各省天气”，而是回答交易员每天最关心的五个问题：

1. 今天从现在起，哪些时间窗口需要先看；
2. 昨日 09:00 对今天的预测，今天发生了什么可追溯修正；
3. 明天有哪些首次进入视野的天气侧信号；
4. 哪些信号可能影响负荷天气压力、光资源或 10 米地面风资源代理；
5. 当前结论何时复核、什么情况会推翻它。

云云只输出气象事实和气象侧代理。没有可追溯的负荷、风光功率预测、机组、联络线及价格数据时，不判断实际供需、电价、仓位、申报价或买卖方向。

## 2. 每日触达节奏

| 时间 | 内容 | 是否必发 | 发送前提 |
|---|---|---:|---|
| 08:50 | 生成 09:00 不可变快照 | 否 | 只计算，不发消息 |
| 09:00 | 完整晨报 | 计划发送 | 上午开关、全局开关、审核目标均通过，且 `DRY_RUN=false` |
| 14:50 | 基于同日 09:00 快照生成差异 | 否 | 必须先读到同日 09:00 快照 |
| 15:00 | 变化快报 | 有变化才发 | 下午独立开关及全部发送门禁通过 |
| 事件发生时 | 紧急预警变化 | 条件触发 | 官方/已审核来源、规则、冷却、频控及发送授权全部通过 |

正常一天主动消息为 1–2 条，默认每日硬上限为 3 条。15:00 无实质变化时保持静默。紧急预警引擎已有连续命中、去重、冷却、升级、恢复和频控能力，但生产侧的定时评估数据链尚未授权接入，因此目前不得开启自动告警发送。

## 3. 09:00 完整晨报

### 3.1 时间范围

- 今日：09:00–24:00；
- 明日：00:00–24:00；
- 已经过的今日时段不再写成“未来风险”；
- 夜间、早峰、午间光伏、下午过渡、晚峰、深夜六类窗口全部检查；
- 某窗口没有达到阈值时明确写“已检查，暂无关注信号”；
- 数据不足时明确写“数据不足”，不能伪装成稳定。

### 3.2 卡片信息顺序

1. 标题、更新时间、分析范围；
2. 一句话结论；
3. 今天先看哪三件事；
4. 今日预测修正；
5. 明日首次观察；
6. 所有时间窗口检查结果；
7. 放心清单说明；
8. 结论有效期及下一次复核；
9. 数据缺失、降级和边界说明。

数据正常时，顶部只展示“更新时间｜分析区覆盖｜总体可信度”。只有数据缺失、质量降级、低可信或用户主动展开时，才展示运行 ID、代理口径、权重版本、抓取/起报/有效时间、来源链接和 SHA-256 内容指纹。

### 3.3 覆盖说明

不再使用“3/3 完整样本”“2/3 部分覆盖”一类难以理解的表达：

| 实际情况 | 用户文案 |
|---|---|
| 3 个配置城市均有数据 | 用于分析的 3 个城市都有数据 |
| 3 个城市中有 2 个 | 用于分析的 3 个城市中，2 个有数据；结论可能不完整 |
| 3 个城市中仅 1 个 | 用于分析的 3 个城市中，仅 1 个有数据；不能代表全区 |
| 整个分析区无数据 | 数据不足，不输出该分析区的风险结论 |

只有一个城市有数据的分析区不会进入全区资源代理排行。

## 4. 比较与风险生命周期

比较必须同时满足：同一分析区、同一目标日期、同一时间窗口、同一代理指标、同一代理口径版本和同一权重版本。任一条件不一致即停止比较，并说明原因。

| 状态 | 含义 |
|---|---|
| 首次观察 | 该目标时段此前没有可比快照，不输出升降结论 |
| 持续关注 | 同一目标时段仍达到关注阈值 |
| 风险升级 | 同一目标时段的严重性明确上升 |
| 风险减弱 | 同一目标时段的严重性明确下降但仍需关注 |
| 结束跟踪 | 同一目标时段已降到阈值以下 |
| 无法比较 | 有效时间、方法版本或溯源信息不一致 |

09:00 的“今日预测修正”基准固定写成“对比昨日 09:00 对今日相同时段的预测”，并附比较批次。明日内容通常属于首次观察，不能拿“昨日的明日”和“今日的明日”这两个不同目标日期做升降比较。

## 5. 15:00 变化快报

15:00 只回答“相较同日 09:00，有哪些事情真的变了”。以下变化可进入卡片：

- 新增风险；
- 风险升级；
- 风险减弱；
- 风险解除；
- 同一确定性事件的关键时段移动；
- 可信度发生有意义的变化。

普通文字相似但没有同一事件 ID 的两条信号，不会被猜成“时段移动”。15:00 快照缺失、过期、不是 15:00 时次、没有同日 09:00 基准或没有实质变化时，外部发送次数都必须为 0。

## 6. 紧急预警

紧急预警仅允许来自已经审核、可追溯的官方适配器。触发逻辑包括：

- 连续命中后才首次触发；
- 同一规则、窗口和等级使用稳定去重键；
- 冷却期内不重复发送；
- 等级升级可越过普通冷却；
- 连续恢复后只发送一次解除；
- 静默时段、小时上限、每日上限均在出站前检查；
- 数据不可用时不触发，也不把“没有数据”解释成“风险解除”；
- `ALERT_SEND_ENABLED=false` 或 `DRY_RUN=true` 时只允许离线评估，飞书调用为 0。

> 2. 山东样本区·济南｜今日 17:00–21:00｜晚峰

>    10 米地面风资源代理增强；驱动：地面风速上升
>    建议核对：风电功率预测及爬坡约束｜可信度：中等
>
> **今日预测修正**
> 对比昨日 09:00 对今日相同时段的预测（演示批次 run-demo-0810-0900）

> 甘肃早峰地面风资源代理增强为首次纳入观察，暂无同时间可比预测。

> 今日：午间光伏有 2 个关注分析区；下午过渡有 1 个；晚峰有 3 个；深夜已检查，无关注信号。

> **结论有效期**
> 计划于 15:00 复核；只有相较本次 09:00 预测出现实质变化才推送快报。官方预警新增或升级、关键时段移动、严重性变化、来源分歧扩大或数据不可用会推翻当前结论。

> **边界**
> 当前为城市代表性扫描。短波辐射/云雨和 10 米风是资源代理，不是实际光伏或风电出力。未接入负荷、出力、机组、联络线及价格数据，不构成交易或报价建议。

回滚顺序：

1. 先关闭 `POWER_BRIEFING_AFTERNOON_ALLOW_SEND` 和 `POWER_BRIEFING_ALLOW_SEND`；
2. 如需总停发，再关闭 `GLOBAL_FEISHU_SEND_ENABLED` 或设置 `DRY_RUN=true`；
3. 保留四个 cron 定义，通过开关停发，不通过删定时任务掩盖问题；
4. 冻结待发送 outbox，保留发送账本和审计记录；
5. 恢复上一稳定镜像、提交和经审核配置；
6. 校验快照数据库迁移及缓存身份后再恢复计算，最后逐时次恢复发送。

## 10. 当前发布阻断

以下事项完成前，不得开启真实生产抓取或主动发送：

1. 逐来源确认准确 endpoint、许可用途、署名、保留期、配额和责任人，并生成生产 `SourcePolicy`；
2. 人工确认真实发送目标、用途、频率、静默时间和审批引用；
3. 为紧急预警定时评估链接入经审核的官方记录，完成端到端演练；
4. 在 `DRY_RUN=true` 下通过全量测试、发布 preflight、同快照校验和回滚演练；
5. 先灰度只计算，再开放被动查询，最后分别审批 09:00、15:00 和紧急预警发送。
