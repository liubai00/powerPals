## 1. 结论摘要

本轮已经把云云从“能回答天气问题的机器人”推进为默认拒绝、来源可追溯、边界明确的电力气象助手底座。P0 安全项、96 条核心回放、晨报 3.0 的同快照发送链、外部来源门禁、上下文隔离、数据最小化和离线发布预检均已在本地完成。

但本项目没有本地自有气象数据，也没有自有负荷、出力、机组、联络线、价格、持仓或资产数据。代码完成不等于已经取得外部数据使用权，更不等于能够上线真实结论。当前缺少逐来源人工许可、生产目标授权、生产身份与密钥注入、备份/监控/回滚证据，因此发布预检按设计返回 `BLOCKED`，不能部署。

## 2. 数据与产品边界

云云本地只承担以下职责：

- 注册并校验第三方或官方来源、精确 endpoint、用途和保留期；
- 保存许可允许的最小 provenance、结构化状态、派生特征、风险结果和审计记录；
- 在来源、时效、单位、完整率或许可不满足时失败关闭；
- 把天气事实转换为“负荷天气压力代理、光资源代理、10 米地面风资源代理、新能源预测复杂度气象代理”等 W1/W2 信号。

以下内容在没有可核验外部电力数据时始终不可输出：

- 实际负荷、实际风光出力、供需缺口和价格方向；
- 报价、申报量、仓位、做多做空或资产调度指令；
- 将搜索摘要、大模型记忆或过期缓存包装成最新结构化事实；
- 将代表点天气包装成全省实况或独立交易市场事实。

## 5. 当前生产发布阻断

离线 preflight 当前失败项包括：

- `production_environment`：本地运行环境不是生产作用域；
- `source_policies_reviewed`：没有完整、人工审核的生产计算来源策略；
- `admin_identity_bound`：生产管理 actor/角色/Token 尚未注入；
- `feishu_bot_identities_bound`：生产双机器人凭证与精确 open_id 尚未复核；
- `shadow_external_effects_disabled`：当前本地运行配置不是一份完整的生产 shadow 配置；
- `release_evidence_current`：缺少当前发布、上一稳定版本、配置哈希、备份、监控、回滚和审批引用。

此外还必须由用户或授权运维确认：

1. 每个真实天气/预警/地理编码/参考数据来源的合同或条款版本、允许用途、署名和保留期；
2. 每个精确生产 endpoint、单位、覆盖、时区、新鲜度、最低完整率、配额和失败降级；
3. 首个且唯一的灰度飞书目标、授权人、频率、静默时段和紧急停发责任人；
4. 数据库可读备份、上一稳定镜像/提交、监控值守和一键停发路径；
5. 至少 7 天只计算、不回复、不发送的生产影子观察结果。

以上任一项缺失时，部署结论必须保持 `BLOCKED`。不得用测试 policy、示例 endpoint、测试 chat_id 或猜测条款绕过。

## 7. 灰度与回滚

建议灰度顺序：

1. 固化提交、镜像、配置 schema 和三个 SQLite 数据库备份；
2. `DRY_RUN=true`，所有回复、主动发送和五项受控能力关闭；
3. 使用真实审核后的 SourcePolicy 影子运行至少 7 天；
4. 只开放内部私聊和电力气象分析，被动回复仍要求飞书认证；
5. 仅开放一个已审核的 09:00 晨报目标；
6. 订阅和主动告警最后单独灰度，不补发历史事件。

回滚顺序：

1. 立即设置 `ALERT_SEND_ENABLED=false`、`GLOBAL_FEISHU_SEND_ENABLED=false`、`DRY_RUN=true`；
2. 冻结 outbox，不补发积压；
3. 保留 08:50/09:00 定义，但停止外部发送；
4. 恢复上一稳定镜像/提交和已验证配置；
5. 保留新增表和审计，不执行破坏性数据库降级；
6. 在隔离环境重放故障后，从单目标重新灰度。
