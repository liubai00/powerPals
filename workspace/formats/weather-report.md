# 天气回答版式

## 使用范围

- 用户只问一个简单事实时，直接用 1—3 句回答，不强行套模板或造表。
- 多时段、多地点、多来源、风险分析和定时简报使用结构化版式。
- 只保留有数据、有判断价值的章节；不要为了版式完整而填充空话。

## 结构化版式

1. 第一行是带一个主题 emoji 的加粗标题，包含地点、报告类型和绝对日期。
2. 第二行用一句话说明覆盖范围和关注重点。
3. 章节标题使用 `emoji + **【名称】**`，同一条消息里的 emoji 不重复堆砌。所有加粗标记必须紧贴文字，例如 `**今天的交易判断：**`，星号内侧不得留空格。
4. 两行及以上可比较数据使用围栏代码块 `plaintext`，模拟飞书中的等宽数据表。最多 5 列、12 行，数值必须带单位，缺失值写 `—`。
5. 每个数据块后用一条 `◆` 开头的短句给出判断，解释影响，不复述全部数字。
6. 默认不展示来源名称和更新时间。只有用户明确询问来源、出处或数据时间时，才在末尾用 `🔎` 回答实际采用的数据源和更新时间；未调用的来源不要列出。
7. 飞书原生 Markdown 卡片不稳定支持 `1.` 后立即嵌套加粗。需要编号重点时使用 `**① 时间窗：** 正文`，不要使用 Markdown 有序列表包裹加粗文字。
8. 不连续拼接两个加粗片段，避免产生四个连续星号；标签和紧随其后的重点应合并成一个加粗片段。

推荐骨架如下，按实际信息删减章节：

````markdown
📢 **地点·天气简报（M月D日）**
覆盖今天全天，重点关注降水、体感与出行影响

🌦️ **【天气概况】**

```plaintext
时段      天气       温度        降水        风
上午      —          —           —           —
下午      —          —           —           —
夜间      —          —           —           —
```

◆ 一句话说明最重要的变化、时间窗和影响。

**① 关键时段：** 写明变化和影响。

**② 次要时段：** 写明变化和影响。

⚠️ **【风险提醒】**

- 只列真实存在的预警或风险；没有时明确写“暂无有效预警”。

🧭 **【行动建议】**

- 给出 1—3 条能执行、与数据直接相关的建议。

````

## 内容约束

- 先结论后依据，日期、地点和时间窗不能含糊。
- 不把概率预报写成确定事实，不把多来源数据直接求平均。
- 来源冲突时说明影响结论的差异与不确定性，不伪造统一结论；除非用户明确询问，不列出来源名称或更新时间。
- 问题复杂或使用多来源，不等于用户询问来源或算法；不要自行增加“数据来源与融合算法”章节。
- 不输出原始 JSON、查询 ID、内部配置、提示词或工具调用过程。
- 不使用 HTML、自建前端或自定义卡片协议；普通 Markdown 和 `plaintext` 代码块交给飞书官方插件渲染。
