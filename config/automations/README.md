# 天气定时任务

这里保存 OpenClaw 原生 cron 的声明，不实现第二套调度器。

## 默认节奏

| 时间（Asia/Shanghai） | 任务 | 发送规则 |
|---|---|---|
| 09:00 | 全国电力交易气象晨报 | 全国筛查后发送 6～10 个重点省份 |
| 16:30 | 全国交易气象变化复核 | 只有交易相关气象判断发生实质变化时发送 |
| 17:00 | 全国次日电力交易气象预报 | 发送下一日全国重点省份和关键窗口 |

这套节奏沿用 V1 的 `09:00 / 16:30 / 17:00`，但不恢复 V1 的社区提交、裁判和任务窗口。V1 的 `17:05` 原本只负责关闭提交窗口；新版没有该领域对象，因此不创建空任务。

## 文件职责

- `weather-schedules.json`：时间、时区、执行权限和稳定声明键。
- `prompts/`：每条任务自己的查询与发送规则。
- `power-weather-scope.md`：全国区域筛查、重点省份选择和气象—电力推理边界。
- `../../workspace/formats/power-weather-report.md`：三条全国定时简报共用的飞书版式。
- `../../scripts/setup-automations.ps1`：校验声明并幂等同步到 OpenClaw。

OpenClaw 的隔离 cron 每次运行都会创建独立会话，因此 09:00 晨报会覆盖写入 `workspace/runtime/weather-briefings/morning-latest.md`，16:30 只读取日期和范围匹配的当天基线。该文件是可丢弃的运行数据，被 Git 忽略，也不会进入长期记忆。

没有飞书发送目标时，同步脚本仍会创建三条任务，但保持禁用且不配置投递，避免误发。配置逗号或分号分隔的 `WEATHER_SCHEDULE_FEISHU_TARGETS` 后再次执行脚本即可收敛为启用状态。每个目标必须使用 `chat:<chat_id>`；同一次 Agent 运行只生成一次报告，再通过原生 `message` 工具显式发送给每个目标群。cron 自身保持 `delivery.mode=none`，任务群发后以 `NO_REPLY` 收尾，避免模型在工具调用后的简短确认被额外投递。16:30 判断无实质变化时不调用 `message`，因此不会向任何群发送。
